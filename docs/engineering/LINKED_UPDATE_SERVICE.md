## Application ports and guarantees

Construct with trusted core functions `readSource(groupId)`,
`readTarget(targetId)`, `render({snapshot,selection})`, and `storage`:

- Source reads return the authoritative snapshot and current exact selection.
- Target reads identify stable target ID, link revision/version, 48 kHz/L/R.
  Labels, destination processors/unrelated audio and whole-project revisions are
  intentionally not rewritten or used as a coarse invalidation key.
- The service rechecks relevant source dependencies and destination link identity
  before rendering, after rendering, and after preparation. It stages copied,
  finite, checksum-verified native PCM with immutable source/selection provenance.
- `storage.prepare(media)` must never promote. A successful preparation returns
  an opaque host token; failure may leave unreachable artifacts that the real
  repository must distinguish from committed generations. No arbitrary paths.
- `storage.commit({prepared,targetId,expected,expectedSource,provenance})` **must
  serialize and atomically validate the expected source dependency key and target
  link revision**, then change only that linked-version pointer and retained
  history. Earlier async reads cannot provide this guarantee. A real adapter must
  coordinate source/target mutation, media/journal durability and recovery; the
  service does not implement or prove those atomicity/storage guarantees.
- `storage.discard(token)` cleans only unpromoted owned staging. The service
  retains both original and cleanup errors. It never discards a potentially
  promoted generation after a commit exception/invalid receipt.

`start` returns an operation with `completion`, `cancel()`, `phase` and an immutable
snapshot of ordered correlated `events`. These backend phases need a host adapter
before mapping to the presentation port; do not wire them directly as UI state.
No fake percentages or completion event are generated by timers.

## Cancellation and ambiguous promotion

Cancel during rendering/preparation logically revokes promotion eligibility,
even if native rendering cannot stop. Cancellation remains requested until the
job settles. After the final eligibility check, entering `storage.commit` is this
service's logical promotion barrier: cancel returns **too-late**, never a false
cancelled/rollback result. This is not the filesystem rename boundary. The future
adapter must compare both guards in its serialized transaction before promotion;
source edits after that linearization point make the committed snapshot older,
not a different render. Later currentness observation reports those updates.

Any throw/invalid receipt after entering commit is conservatively **uncertain**,
not failed-with-rollback. The target is blocked for further reviews/starts until
real durable reconciliation. There is deliberately no blind clear/retry API.
An adapter can refine known pre-promotion conflicts later through a reviewed
result contract; generic errors cannot safely imply that nothing was committed.

### Serialization, publication and history

- One exclusive writer lease plus an in-process queue covers source edits,
  destination edits, source/target guard validation, and complete pointer
  publication. A second writer fails closed, including stale post-crash leases.
  Read-only readers can coexist; they never recover by guessing a new generation.
- Canonical PCM is copied/validated/checksummed, exclusively written and synced;
  immutable content-addressed files may be shared, never overwritten by update.
  Commit rechecks actual persisted media instead of trusting staged memory.
- Generation and journal are synced/published before a synced temporary pointer
  is atomically renamed over CURRENT and its directory synced. Pointer, journal,
  generation, schema, asset identities, finite media and SHA-256 are verified on
  reopening. Only CURRENT selects a generation; unreachable/partial artifacts
  never become active by directory scan. Corrupt referenced data fails closed.
- Commit compares the exact source dependency closure and destination link
  revision **inside this single writer queue**. It merges only a link pointer,
  retained version/provenance and history into freshly loaded current state.
  Processor/unrelated changes survive; reads alone are not the atomic mechanism.
- Undo/redo publish another journaled generation and advance link revision while
  preserving current source, manual destination processing, unrelated media and
  all retained versions. A new commit after undo clears redo eligibility, without
  deleting those retained versions. Stale history actions reject by link revision.
- Cancellation releases preparation eligibility without deleting potentially
  shared blobs. A commit I/O ambiguity poisons the writer; it must be closed and
  current state verified on reopening. No blind uncertain-result retry/rollback.

`src/audio/linkedSessions/renderLinkedDestination.js` renders reopened linked
media through actual native destination gain/peaking EQ and mixes actual unrelated
media, using stored parameters and frame placement. It validates bounded built-in
parameters, not arbitrary plugins/code, and disconnects created nodes on failure.

### Third slice — writable recovery and explicit quarantine, 2026-10-16

New schema-2 stores use a permanent kernel-lock inode and installed
`/usr/bin/flock` through an inherited Node descriptor, not PID liveness. All
committed lineage/media must validate before atomic epoch handoff. Live writers
cannot be displaced by a cooperating contender. Old schema-1 stores remain
readable, never silently migrated. This Linux runtime requirement is not a new
npm dependency or a portable production/Electron solution.

Explicit `inspectOrphans`/`quarantineOrphans` protect the complete committed
lineage, shared/registered/retained/history media and active preparations. Opaque
plans are revalidated under the queue/owner; private synced manifests precede
renames. Unknown/unsafe files and existing archives remain untouched. No deletion
or automatic orphan promotion/cleanup. See the [full protocol and limits](LINKED_WRITER_RECOVERY.md).
